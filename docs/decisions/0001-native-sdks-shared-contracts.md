# ADR-0001：三端原生 SDK，共享合同与 SQLite 模型

状态：已接受  
日期：2026-08-14

## 背景

项目需要同时支持 Swift、Android/Kotlin 和 OHOS/ArkTS。OAuth、平台安全存储、目录授权、后台调度和媒体来源访问高度依赖平台；文件名解析、扫描状态机、同步格式和数据库语义则需要保持一致。

## 决策

首版采用三端原生实现：

- Swift Package；
- Android/Kotlin library；
- OHOS ArkTS HAR。

三端共享而不是重复发明的内容放入 `specs/`：

- 数据模型与 wire format；
- SQLite DDL、迁移和约束；
- 状态机、错误分类和冲突规则；
- parser、扫描和同步测试向量；
- 行为级验收标准。

不直接共享活动 SQLite 文件，也不在首版引入 KMP、C++ 或 Rust 公共运行时。

## 原因

- OAuth 回调、安全存储、文件授权和后台执行需要平台原生集成；
- OHOS 与 Apple/Android 的工具链和 ABI 差异较大；
- 先稳定合同比过早统一运行时风险更低；
- 业务规则可通过 fixture 和迁移 checksum 保持一致；
- 后续若 parser 或同步合并算法成为维护瓶颈，可基于性能数据再抽取共享核心。

## 后果

优点：

- 平台体验和系统能力更自然；
- 发布、调试和安全审计边界清晰；
- 单个平台不被另一平台工具链阻塞。

代价：

- 同一业务规则需要三份实现；
- 必须投入跨平台契约测试；
- API 命名虽符合各语言习惯，语义仍需严格对齐。

## 重新评估条件

出现下列任一情况时重新评估共享运行时：

- parser/匹配代码占三端缺陷的大多数；
- 数据库迁移长期发生行为漂移；
- 性能热点明确且跨平台一致；
- OHOS 对目标共享技术的工具链支持达到稳定发布要求。
